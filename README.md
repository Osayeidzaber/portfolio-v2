## The idea

**Black Press** is a portfolio told in numbered chapters: Cover, About, Work, Toolkit,
Ledger, Experience, Recognition, Workbench, and Contact. Pure black surfaces, white
type, fine rules, and a mix of Bricolage Grotesque, Instrument Serif, and JetBrains Mono
give it an editorial feel. Original-color project screenshots sit within the monochrome interface.

GitHub powers both the project feed and the content system. The studio publishes JSON
back to the repository, so edits have a commit history without needing a database.

## Inside the portfolio

- **An interactive cover** with variable typography, a light tunnel, and animated roles.
- **Selected work** in a WebGL carousel, a Corso Velle showcase, and individual case-study
  pages with server-rendered repository READMEs.
- **A GitHub ledger** with repositories, languages, and activity from real API data. A
  bundled snapshot keeps content available when the API cannot be reached.
- **A Minecraft workbench** with coordinate conversion, stack and XP calculators,
  gradient and color tools, MOTD previews, and item-name formatting, plus an optional
  lab for shader and typography experiments.
- **A private studio** at `/admin` for editing, reordering, uploads, draft previews,
  publishing, and restoring content history.
- **Motion fallbacks** for reduced-motion preferences and unavailable WebGL, with
  effects mounted near the viewport and released when they leave it.

Unknown achievements and other placeholder content stay hidden until filled in.

## Run locally

Use **Node.js 22 LTS or newer** and **pnpm 10.34.9**, as pinned in `package.json`.

```bash
git clone https://github.com/Osayeidzaber/portfolio-v2.git
cd portfolio-v2
pnpm install --frozen-lockfile
pnpm dev
```

Open [localhost:3000](http://localhost:3000). No environment variables are required
to browse the public site: bundled content and the public GitHub API provide the defaults.

To enable the local studio:

1. Copy `.env.example` to `.env.local`.
2. Run `pnpm hash-password` and choose a password of at least 12 characters.
3. Paste the generated `ADMIN_PASSWORD_HASH` and `SESSION_SECRET` into `.env.local`.
4. Restart the development server and visit [localhost:3000/admin](http://localhost:3000/admin).

During development, saves use local content files unless GitHub publishing is configured.
Production publishing requires a content repository and a write token.

## Configuration

[`.env.example`](.env.example) documents every variable. Keep real credentials in
`.env.local` or your deployment environment; `.env.local` is ignored by Git.

| Variable | Purpose |
| --- | --- |
| `NEXT_PUBLIC_SITE_URL` | Your deployed site's canonical URL; set this in production |
| `GITHUB_USERNAME` | Profile to display; defaults to `Osayeidzaber` |
| `GITHUB_TOKEN` | Optional read token for higher API limits and contribution-calendar access |
| `GITHUB_CONTENT_REPO` | Set to `Osayeidzaber/portfolio-v2` for production studio publishing |
| `GITHUB_CONTENT_BRANCH` | Content branch; defaults to `main` |
| `GITHUB_CONTENT_TOKEN` | Fine-grained token with **Contents: read and write** for this repository |
| `ADMIN_PASSWORD_HASH` | Password hash generated by `pnpm hash-password` |
| `SESSION_SECRET` | Session-signing secret generated by the same command |
| `GITHUB_WEBHOOK_SECRET` | Shared secret for GitHub webhook verification |
| `REVALIDATE_SECRET` | Optional bearer secret for manual cache refresh |

All tokens, password hashes, and session secrets are server-only. Only the canonical
site URL uses the `NEXT_PUBLIC_` prefix.

## Edit and publish

1. Sign in at `/admin` and choose a section.
2. Edit text, reorder entries, or upload project media and a résumé.
3. **Save draft → Preview draft → Publish.**
4. Review the publish commit or restore an earlier version from the studio history.

```text
Studio → authenticated server action → content validation
                                      ↓
                             GitHub Contents API
                                      ↓
                         JSON commit + cache update
                                      ↓
                              Public portfolio
```

Published content lives in `content/site.json`; drafts use `content/draft.json`, and
uploads live in `content/uploads/`. Saves include the last-seen file SHA. If another
edit has changed the file, the studio surfaces a conflict instead of overwriting it.

GitHub data refreshes hourly. A verified webhook invalidates its cache sooner, and
`pnpm build` refreshes the bundled snapshot before building. Without a read token,
the Ledger uses a clearly labeled public-events fallback rather than the full
contribution calendar.

## Deploy to Vercel

1. Import [`Osayeidzaber/portfolio-v2`](https://github.com/Osayeidzaber/portfolio-v2)
   into Vercel as a Next.js project.
2. Set `NEXT_PUBLIC_SITE_URL` to the production URL.
3. To enable the studio, configure the content repository, branch, write token,
   password hash, and session secret listed above. Generate fresh production credentials.
4. Add `GITHUB_TOKEN` for authenticated GitHub reads and `GITHUB_WEBHOOK_SECRET`
   for webhook verification.
5. In GitHub repository settings, add a webhook:
   - **Payload URL:** `https://<your-domain>/api/github/webhook`
   - **Content type:** `application/json`
   - **Secret:** the same value as `GITHUB_WEBHOOK_SECRET`
   - **Events:** push events
6. Deploy after configuring the environment. Add webhooks to featured project
   repositories if their pushes should also refresh portfolio data immediately.

Vercel can deploy future pushes to `main` and create previews for pull requests.
Uploaded media is served through `/media/…` so repository-backed uploads can be
read before a deployment completes.

## Stack and structure

| Layer | Tools |
| --- | --- |
| Application | Next.js 16 App Router, React 19, TypeScript |
| Styling | Tailwind CSS 4, shadcn registry components |
| Animation | GSAP + ScrollTrigger, Motion |
| Graphics | Three.js, React Three Fiber, ogl |
| Content | GitHub REST / GraphQL, JSON, Zod |
| Verification | Vitest, Playwright, axe accessibility checks |
| Hosting | Vercel |

```text
content/                 Published content, drafts, uploads, GitHub snapshot
scripts/                 Snapshot sync and password generation
src/app/(site)/          Homepage and /work/[slug] case studies
src/app/admin/           Authenticated studio, login, and previews
src/app/api/             Webhook, revalidation, and thumbnail endpoints
src/components/site/     Portfolio chapters and composition
src/components/shaders/  Custom shader experiments
src/lib/content/         Schema, reading, writing, and conflict handling
src/lib/github/          API clients, ranking, READMEs, and webhook verification
src/lib/auth/            Passwords, signed sessions, and rate limiting
tests/                   Unit tests
e2e/                     Browser and security checks
```

The interface combines registry components from React Bits, Aceternity, Magic UI,
Fancy, and UI Arc. Two unavailable Aceternity Pro blocks were replaced with custom
implementations. The full component map and architectural decisions are in [PLAN.md](PLAN.md).

## Commands and verification

| Command | Purpose |
| --- | --- |
| `pnpm dev` | Start the development server |
| `pnpm build` | Refresh the snapshot and create a production build |
| `pnpm start` | Serve the production build |
| `pnpm typecheck` | Check TypeScript |
| `pnpm lint` | Run ESLint |
| `pnpm test` | Run unit tests |
| `pnpm test:e2e` | Run desktop and mobile Chromium checks against a production build |
| `pnpm hash-password` | Generate studio login credentials |
| `pnpm snapshot:github` | Refresh the offline GitHub data |

Run the complete verification sequence before shipping:

```bash
pnpm typecheck && pnpm lint && pnpm test && pnpm build && pnpm test:e2e
```

Install Chromium with `pnpm exec playwright install chromium` if it is missing.
Browser tests start the production server on port **3100**. Set
`E2E_ADMIN_PASSWORD` to include authenticated studio checks.

## Practical notes

- **Public site works; studio is disabled:** configure the password hash and a
  session secret of at least 32 characters, then restart or redeploy.
- **GitHub data looks stale:** add a read token, check webhook configuration, or
  refresh the bundled snapshot. Public API rate limits can trigger snapshot fallback.
- **Production publishing is unavailable:** check the content repository and the
  write token's repository access and Contents permission.
- **Mobile performance:** the animation-heavy page still needs a lighter mode for
  low-power devices. Earlier local Lighthouse runs measured roughly 60 mobile performance;
  those measurements are historical, not a guarantee for a deployed site.
- **Browser coverage:** automated checks use Chromium desktop and mobile emulation.
  Real devices, Safari, and Firefox need separate verification.
- **Login rate limiting:** the in-memory limiter applies per server instance.
